# Тесты стиля

Открывают живую ленту DeviantArt в настоящем Firefox, прокручивают её и замеряют то, на что
жалуются пользователи: скачки контента, пустые места и обрезанные картинки. Итог — вердикт и код выхода.

Тесты ходят на настоящий сайт, поэтому результат зависит от текущей вёрстки, содержимого ленты и сети.

## Что нужно

- Node.js 24 или новее (нужен встроенный `WebSocket`). Устанавливать пакеты не надо.
- Firefox. Если его нет в `PATH`, укажите путь через `--firefox` или переменную `FIREFOX_BIN`.
- Куки тестового аккаунта — по желанию, см. ниже.

Каждый запуск поднимает отдельный процесс Firefox в headless-режиме с временным профилем. Ваш профиль
и открытый браузер не затрагиваются.

## Запуск

Из корня репозитория:

```sh
node tests/run.mjs                      # текущий файл стиля, все страницы; без куки 10–15 минут, с куками дольше
node tests/run.mjs --pages tag --no-images --no-control   # быстрая проверка, около минуты
node tests/run.mjs --compare 07427a6    # рядом с другой версией из git
node tests/run.mjs --css main           # версия из git вместо рабочего файла
node --test tests/unit.test.mjs         # тесты без браузера и сети, меньше секунды
```

Все параметры: `node tests/run.mjs --help`.

## Куки

Без куки тесты работают, но анонимная лента обрывается на 10 строках, поэтому бесконечная подгрузка
не проверяется. Для полной проверки:

1. Войдите в **тестовый** аккаунт, не в основной: кука `auth` даёт полный доступ к аккаунту.
2. Экспортируйте куки deviantart.com в файл `tests/cookies.txt` или `cookies.txt` в корне. Подходят
   формат Netscape, JSON из Cookie-Editor и строка заголовка `Cookie`.
3. Запустите тесты. После работы выйдите из аккаунта, чтобы сессия стала недействительной.

Файлы `cookies.txt` и папка `tests/out/` исключены в `.gitignore`. Значения куки никуда не выводятся,
а куки других сайтов отбрасываются. На скриншотах в `tests/out/` виден аккаунт.

## Что проверяется

| Проверка | Условия | Провал, если |
|---|---|---|
| Нет догрузки без прокрутки | 10 с без действий | число строк выросло |
| Прокрутка вниз, вверх, быстрая | anchoring выключен | на экране есть пустое место или строки сдвинулись больше чем на 2px, а часть карточек при этом выгружена |
| Картинки без обрезки | после прокрутки | пропорции на экране отличаются от настоящих больше чем на 2% |
| Аватары не растянуты | после прокрутки | заглушка аватара шире своего инлайн-размера |
| Низ экрана свободен | под логином, настоящая плашка веб-приложения | у нижнего края есть закреплённый элемент |
| Картинки: чтение | 400px/с, без задержки и с задержкой | строки сдвинулись |
| Картинки: быстро вниз, назад | 1800 и 1200px/с | только предупреждение: это открытая проблема №4 из [PROBLEMS.md](../PROBLEMS.md) |

Без куки проверяются `tag`, `morelikethis` и `home`, с куками ещё `search`, `daily`, `gallery`,
`favourites`, `profile` и `watch`. Страница без ленты с карточками пропускается. Например, `watch` у
аккаунта без подписок показывает подбор авторов, поэтому настоящая лента подписок там не проверяется.

Сдвиг при всех смонтированных карточках помечается `warn`: выгрузки не было, значит, сдвиг дала
догрузившаяся на экране картинка (проблема №4). Строка с выгруженными карточками считается провалом.

Плашка показывается только аккаунтам старше 30 дней. Чтобы проверить её на новом тестовом аккаунте, тест
меняет дату регистрации в данных страницы. Правка действует только в этом временном браузере, на сайт
ничего не отправляется.

**Scroll anchoring** выключен настройкой браузера в сценариях прокрутки. Иначе Firefox сам компенсирует
сдвиг, и тест его не увидит, а на телефоне этот механизм отключается после серии подстроек. Сценарии с
картинками идут с настройками по умолчанию.

## Результат

| Код | Значение |
|---|---|
| `0` | провалов нет, предупреждения `warn` допустимы |
| `1` | есть хотя бы одна строка `FAIL` |
| `2` | проверка недействительна: результатам нельзя верить |

Код `2` получается, если сайт не принял куки, ни на одной странице нет ленты, контрольная версия не дала
скачков или неверно указаны параметры.

Строка «не проверено» значит, что прокручивать было некуда. Это не успех: сценарий не выполнялся.

**Контрольный прогон.** В конце тест запускает версию 0.2.0 из `tests/fixtures/`, в которой скачки есть
точно. Если тест их не нашёл, значит, он ослеп, и его нули ничего не значат. Такое уже случалось с
черновой версией, поэтому контроль включён по умолчанию.

Отчёт и скриншоты сохраняются в `tests/out/`.

## Что тесты не заменяют

- **Телефон.** Это десктопный Firefox с мобильным User Agent и окном 400×900: другой движок прокрутки и
  другие ограничения памяти. Расход памяти на длинной ленте не измеряется, есть только число элементов DOM.
- **Stylus.** Стиль подключается через `adoptedStyleSheets` до скриптов страницы, а не расширением.
- **Настоящий жест.** Прокрутка идёт шагами `scrollBy`, а не плавным движением пальца.

## Когда результат может ввести в заблуждение

- **Параллельные запуски** под одним аккаунтом не делайте: сессии мешают друг другу, и страница может не
  загрузиться. Сам `run.mjs` работает последовательно.
- **Сценарии с картинками зависят от сети.** Если единичный `FAIL` в строке «чтение» не повторяется,
  дело скорее в сети.
- **Селекторы привязаны к вёрстке** (`data-testid="grid-row"`, `section`). Если сайт её поменяет, страницы
  будут пропускаться, а без единой ленты вы получите код `2`.
- **URL страницы `morelikethis`** ведёт на конкретную работу. Если её удалят, замените адрес в `run.mjs`.

## Устройство

| Файл | Назначение |
|---|---|
| `run.mjs` | командная строка, вердикты, отчёт |
| `lib/scenarios.mjs` | сценарии: открытие ленты, прокрутка, задержка картинок |
| `lib/probe.browser.js` | код в странице: шаг прокрутки и покадровые замеры |
| `lib/firefox.mjs` | запуск Firefox и клиент WebDriver BiDi |
| `lib/cookies.mjs` | разбор файла с куками |
| `lib/usercss.mjs` | загрузка версии стиля, снятие обёрток Stylus |
| `fixtures/control-0.2.0.user.css` | контрольная версия со скачками |
| `unit.test.mjs` | тесты без браузера и сети |
