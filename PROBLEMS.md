# Известные проблемы

Рабочие заметки о том, что не так с мобильной лентой DeviantArt и что уже пробовали.

Окружение пользователя: Firefox для Android + Stylus, ширина экрана ≤ 700px.

Как проверялось (0.3.0): код бандла `da-browse` 1.11671.0 и живая страница в headless Firefox
для десктопа с мобильным User Agent, окно 400×900, тестовый аккаунт. На телефоне 0.3.0 ещё не
проверялся.

## Как устроена лента

Раскладку выбирает `BrowseThumbLayout`. На мобильном это `MobileGrid`, строки которого рисует `Grid`:

```
[data-testid="grid-row"]      обёртка, живёт всё время
  (блок вставки, например <section> «Recommended for You», есть не в каждой строке)
  div                         VisibleGridRow с карточкой <section> или пустой HiddenGridRow
```

- У div инлайн-стили `height`, `contain: size`, `contain-intrinsic-size`. Высота одна на все строки
  и не зависит от картинки.
- Близость к экрану считает хук по `getBoundingClientRect()` обёртки: запас один экран вверх и вниз,
  проверка на `scroll` с троттлингом 375 мс. Высоты берутся реальные, а не расчётные.
- `VisibleGridRow` и `HiddenGridRow` — разные компоненты, поэтому при выгрузке React создаёт новый
  div. Запомненный браузером размер (`contain-intrinsic-size: auto`) на новый div не переходит.
- Следующие страницы подгружает `PagingWrapper` по расстоянию до конца страницы (1000px), строки
  в этом не участвуют. Waypoint на обёртке появляется только если передан `onOffsetReached`.
  `BrowseThumbLayout` его в `MobileGrid` не передаёт, но другие компоненты сайта этот проп используют.

В `more-like-this-page-source.html` другая раскладка: `Torpedo`, строки `[data-testid="content_row"]`
с нативным `content-visibility: auto`. Стиль её не трогает: там высоты уже верные.

## 1. Картинки обрезаны под одну высоту — решено (0.2.0)

Ширина 100%, высота `auto`, `object-fit: contain`. Побочный эффект: строки стали выше инлайн-высоты,
отсюда проблемы 2 и 3.

## 2 и 3. Скачки и разрывы в ленте — решено (0.3.0)

**Причина:** при выгрузке карточка заменяется пустым div с другой высотой.
- 0.2.0: высота заглушки инлайн-значение, строки над экраном схлопываются, контент прыгает.
- 0.2.1: `contain-intrinsic-size: auto` не сработал, потому что div новый. Заглушка получала запасные
  `100vw`: строка 524px становилась 400px. Размер снова не совпадал, и добавлялись пустые места.
  На макете этого не было видно: там div не заменялся.

**Исправление:** виртуализация отключена. Обёртка получает `display: contents`, её rect нулевой, и хук
считает строку видимой всегда, поэтому заглушек больше нет.

Замер, 80 строк под логином, scroll anchoring выключен, чтобы он не скрывал сдвиги:

| | 0.2.1 | 0.3.0 |
|---|---|---|
| Вниз, 450px за шаг | сдвиг на 53 шагах из 60, до 319px | 0 |
| Вверх, 450px за шаг | сдвиг на 39 шагах из 40, до 578px | 0 |
| Быстро вниз, 2500px за шаг | сдвиг на 8 шагах из 8, до 1060px | 0 |
| Пустое место на экране | до 868px | 0 |

**Не воспроизведено:** постоянный разрыв, который видели на телефоне. В 0.2.1 пустое место оставалось на
момент окончания шага (284px через 400 мс), но проверки дольше не было. В 0.3.0 пустых строк нет вообще.

**Цена:** карточки не выгружаются, DOM растёт вместе с лентой: около 5800 элементов против 950 на
80 строках. Как это скажется на очень длинной прокрутке на телефоне, не измерялось.

**Риск:** `display: contents` обнуляет rect и для Waypoint. Там, где обёртка получает `onOffsetReached`,
событие сработает сразу у всех строк. Самопроизвольной подгрузки на «More like this» нет: 10 строк
без прокрутки. Главная и подписки под логином не проверялись.

## 4. Сдвиг от картинки, которая догружается на экране — открыто

Пока картинка не загружена, её пропорции неизвестны и строка низкая. Загрузка на экране сдвигает
карточки ниже. Замер 0.3.0, anchoring включён, все карточки на экране:

| Задержка картинок | Чтение, 400px/с | Быстро, 1800px/с | Назад, 1200px/с |
|---|---|---|---|
| без задержки | 0 | 0 | 0 |
| 500 мс | 0 | 6 сдвигов, до 317px | 0 |
| 500 мс, пропорции заданы заранее | 0 | 0 | 0 |

Стилем это не исправить: пропорции есть в URL картинки (`/v1/fill/w_525,h_350`), но CSS не умеет их
оттуда получить. Последняя строка таблицы получена скриптом в тесте, который выставляет `aspect-ratio`
из URL. Для пользователей такой скрипт потребует Violentmonkey или Tampermonkey.
