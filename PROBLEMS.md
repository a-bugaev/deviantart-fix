# Известные проблемы

Рабочие заметки о том, что не так с мобильной лентой DeviantArt и что уже пробовали.
Все выводы о вёрстке сделаны по описанию в комментариях стиля и по поведению на телефоне:
живую страницу (DOM, скрипты) напрямую ещё не смотрели, поэтому всё, что помечено как
гипотеза, нужно проверить на реальном коде страницы.

Окружение: Firefox для Android + Stylus, ширина экрана ≤ 700px.

## Как устроена лента (по текущим представлениям)

- Лента («More like this», главная, подписки) состоит из строк `[data-testid="grid-row"]`.
  В мобильной ленте в каждой строке одна карточка: `grid-row > div > section`.
- Размеры заданы инлайн-стилями: у div строки `width: 450px; height: 361px`,
  картинка вписана через `object-fit: cover`. На div также стоят `contain` /
  `contain-intrinsic-size` (стиль их сбрасывает).
- Лента виртуализирована: когда строка далеко уходит за экран, `<section>` удаляется,
  а пустой div остаётся и держит место своей инлайн-высотой.
- Неизвестно: как именно React-код решает, какие строки отрисовывать
  (IntersectionObserver на строках или расчёт по scrollTop и своим высотам),
  переиспользуется ли тот же div при возврате карточки, есть ли в ленте строки
  с другим содержимым (реклама, баннеры, скелетоны загрузки).

## 1. Картинки обрезаны под одну высоту — решено (0.2.0)

Все карточки 450×361 с `object-fit: cover`, картинка видна не целиком.

Решение: для строк с одной карточкой ширина 100%, высота `auto`, картинка
`object-fit: contain`, `height: auto`. Картинки видны целиком на всю ширину экрана.

Побочный эффект: строки стали выше, чем считает сайт, отсюда проблемы 2 и 3.

## 2. Скачки ленты при прокрутке — исправлено (0.2.1), но см. п. 3

**Симптом:** контент периодически резко сдвигается во время прокрутки.

**Причина:** строка, ушедшая за верх экрана, теряет `<section>` и возвращается
к инлайн-высоте 361px, хотя на экране была выше. Всё содержимое ниже сдвигается
вверх на разницу. Firefox компенсирует такие сдвиги (scroll anchoring), но после
серии частых подстроек отключает механизм для этого контейнера — поэтому прыжки видны.

**Исправление (0.2.1):**
- строки с карточкой получают `contain-intrinsic-size: auto 100vw auto 100vw` —
  браузер запоминает их отрисованный размер;
- опустевшие строки (`grid-row > div` без прямого потомка `section`, в лентах, где есть
  строки с одной карточкой) получают `height: auto`, `content-visibility: hidden` —
  и их высота берётся из запомненного размера; у ни разу не отрисованных строк —
  запасные `100vw`.

Проверено на макете в Chromium (строка сохраняет 618px вместо 361px) и на телефоне:
скачков больше нет.

## 3. Разрывы в ленте — открыто (появилось с 0.2.1)

**Симптом:** в ленте пустые промежутки.
- Разрывы **не заполняются** со временем.
- По мере прокрутки их **не становится больше**.

**Гипотезы (от более к менее вероятной):**

1. **Правило для пустых строк задевает строки, которые не пусты.** Селектор
   `div:not(:has(> section))` ловит любую строку, где нет `section` *прямым* потомком:
   рекламный слот, баннер, скелетон, строку, где карточка обёрнута ещё одним div.
   `content-visibility: hidden` прячет всё их содержимое, а высота становится
   запомненной или запасной (`100vw`) — получается постоянная пустая область.
   Хорошо сходится с наблюдениями: разрывы не заполняются и не накапливаются.
   Быстрая проверка: заменить `:not(:has(> section))` на `:empty`.
2. **Ни разу не отрисованные строки с запасной высотой `100vw`.** Если сайт по
   какой-то причине не монтирует в них карточку, они остаются пустыми блоками
   высотой с экран.
3. **Расхождение реальных высот и расчёта сайта.** Если виртуализация считает
   видимые строки по своим высотам (361px), а не по реальным, сайт выгружает
   карточки, которые на самом деле на экране. Наблюдения скорее против этого:
   такие разрывы должны накапливаться по мере прокрутки, а их не становится больше.

## 4. Подёргивания при возврате карточек — возможно

При прокрутке вверх карточка монтируется заново, картинка может на мгновение
иметь нулевую высоту (пока не декодирована из кэша), затем вырасти до полной.
CSS не знает пропорций картинки заранее, поэтому стилем это не исправить.
С JS можно запоминать размер карточки или пропорции картинки (`naturalWidth` /
`naturalHeight`) и выставлять `aspect-ratio` заранее.

## 5. Ограничения чистого CSS

- Нельзя узнать пропорции картинки до загрузки.
- Нельзя повлиять на то, как React-код решает, какие строки отрисовывать.
- Любая строка, которая на экране выше, чем считает сайт, даёт либо скачки
  (если строки над экраном сжимаются обратно), либо риск разрывов (если не сжимаются).

## Что собрать для решения на JS + CSS

Удобнее всего с компьютера: десктопный Firefox, режим адаптивного дизайна
(Ctrl+Shift+M) с мобильным User Agent — параметры телефона показывает `userAgent.html`.
Либо отладка телефона по USB через `about:debugging`.

1. URL страницы, где воспроизводится (главная, «More like this», подписки).
2. `outerHTML` контейнера ленты (родитель строк `[data-testid="grid-row"]`):
   - сразу после загрузки;
   - после прокрутки, когда видны разрывы.
3. Для элемента-разрыва: тег, классы, инлайн-стили, есть ли внутри содержимое,
   какие правила стиля к нему применились (вкладка «Правила» в инспекторе).
4. Есть ли у строк или их предков `overflow-anchor`, `content-visibility`,
   `transform` / `position: absolute` (абсолютное позиционирование строк меняет картину).
5. По возможности — как сайт виртуализирует ленту: поиск по скриптам
   `IntersectionObserver`, `grid-row`, обработчики `scroll`.
6. Версия Firefox на телефоне.

## Идеи для JS + CSS

- Запоминать реальную высоту каждой строки (`ResizeObserver`) и при выгрузке карточки
  выставлять её пустой строке инлайн, только для строк с одной карточкой —
  то же, что делает 0.2.1, но точно и без задевания других строк.
- Выставлять картинкам `aspect-ratio` по запомненным `naturalWidth` / `naturalHeight`,
  чтобы карточка сразу занимала нужную высоту.
- Если виртуализация считает по своим высотам — искать способ передать ей реальные
  высоты или ослабить выгрузку (больший запас строк вокруг экрана).
- Скрипт для Violentmonkey / Tampermonkey (оба работают в Firefox для Android).
